## 1. Обзор проекта

| Параметр | Значение |
|---|---|
| **Название** | `MythicPassiveSkills` |
| **Тип** | Аддон для MythicMobs |
| **Платформа** | Paper / Spigot |
| **Версия Minecraft** | 1.20+ |
| **Версия MythicMobs** | 5.x+ |

**Цель:** Создать плагин, который позволяет привязывать выполнение скиллов MythicMobs к игрокам на основе наличия у них определённых Permission-нод. Скиллы работают как «пассивные»: выполняются циклически (с заданным интервалом) или по внутренним триггерам (например, при приседании), пока у игрока есть соответствующее право.

## 2. Функциональные требования

### 2.1. Привязка к Permission

- Плагин проверяет наличие у игрока указанной Permission-ноды (через `Player.hasPermission()` или LuckPerms API для отслеживания изменений в реальном времени).
- Если право есть — «пассивка» активна. Если право снимается или игрок выходит из игры — выполнение скилла прекращается.
- Поддерживается отслеживание изменения прав «на лету» (без перезахода игрока).

### 2.2. Режимы выполнения (Триггеры)

Реализовать как минимум два режима работы пассивных скиллов:

#### 2.2.1. Циклический (Interval)
- Скилл выполняется каждые N тиков, пока активна пассивка.
- **Аналог:** механика `Aura` в MythicMobs с параметрами `onTick` и `interval`.
- **Параметры:** `interval` (в тиках), `Skills` (список навыков для вызова).

#### 2.2.2. Событийный (Triggered)
- Скилл выполняется при наступлении определённого события в игре (`onSneak`, `onAttack`, `onJump` и т.п.).
- **Параметры:** `Trigger` (тип события), `Skills` (список навыков).
- **Важно:** событие проверяется только для игроков, у которых активна пассивка.

### 2.3. Условия выполнения (Conditions)

- Плагин поддерживает проверку условий перед выполнением скилла (`?sneaking`, проверка здоровья, мира и т.д.).
- Используется **стандартный синтаксис условий MythicMobs** — плагин не изобретает свой парсер.
- Условия проверяются перед каждым срабатыванием (для циклического режима — перед каждым тиком).

## 3. Технические требования и архитектура

### 3.1. Зависимости

- **MythicMobs API** (5.x+) — доступ через `MythicBukkit.inst()`.
- **Paper/Bukkit API** (1.20+).
- **LuckPerms API** (опционально, но рекомендуется для отслеживания изменений прав в реальном времени).

### 3.2. Ключевые классы и регистрация (MythicMobs API)

#### 3.2.1. Регистрация кастомного Механизма (Mechanic)

Плагин регистрирует кастомный механизм, который можно вызывать из YAML-конфигов MythicMobs (например, `passive{...}`).

- **Интерфейс:** `ITargetedEntitySkill`.
- **Событие загрузки:** слушать `MythicMechanicLoadEvent`.
- **Регистрация:** в обработчике события проверять `event.getMechanicName().equalsIgnoreCase("PASSIVE")` и вызывать `event.register(new PassiveMechanic(event.getConfig()))`.
- **Конструктор:** принимает `MythicLineConfig` для парсинга параметров (`permission`, `skill`, `interval`, `trigger` и т.д.).
- **Метод `castAtEntity`:** основная логика. Проверять, является ли цель игроком (`target.isPlayer()`), проверять Permission, и если всё ок — либо запускать таймер (циклический режим), либо регистрировать слушателя событий (триггерный режим).

#### 3.2.2. Кастомные Триггеры (SkillTrigger)

Для режима «по событию» создаются кастомные триггеры MythicMobs (например, `~onSneakPassive`).

- **Создание:** `SkillTrigger.create("SNEAK", ...)` + `register()`.
- **Обработка:** слушать `MythicPostReloadedEvent`, чтобы собрать все скиллы, привязанные к новому триггеру. При наступлении игрового события (`PlayerToggleSneakEvent`) вручную вызывать выполнение скиллов через `MythicBukkit.inst().getSkillManager().cast(...)`.

### 3.3. Логика работы (Runtime)

#### 3.3.1. Циклический режим (Interval)

1. Проверить Permission.
2. Запустить `BukkitRunnable` (или использовать `BukkitScheduler`), который каждые N тиков вызывает `MythicBukkit.inst().getSkillManager().cast(...)`.
3. Хранить активные задачи в `Map<UUID, Map<String, Integer>>` (игрок → профиль → ID задачи).
4. Отменять задачу при:
   - выходе игрока (`PlayerQuitEvent`);
   - снятии прав (через LuckPerms listener);
   - выгрузке мира;
   - вызове `/mm reload`.

#### 3.3.2. Событийный режим (Triggered)

1. Проверить Permission.
2. Зарегистрировать слушателя Bukkit для соответствующего события.
3. В обработчике события проверять, активна ли пассивка у игрока, и вызывать `cast`.
